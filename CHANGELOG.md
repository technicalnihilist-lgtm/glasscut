# Changelog

1.1.7 — mask scratch buffers reused instead of reallocated (wand flood + coarse-to-fine cutout, island colour sums folded into the labelling pass, per-pixel closure in the full-res snap removed); a no-op Auto/Wand no longer wipes the redo stack; a second finger can no longer fork a stroke — measured in headless Chrome at 1400x1200: Auto 23.1 MB -> 5.05 MB allocated and 861 ms -> 632 ms median, wand tap 11.76 MB -> 3.36 MB, two-finger gesture 2 undo entries -> 1, redo survives a no-op Auto, zero console errors.
1.1.8 — render loop par frame koi allocation nahi bachti (background aur depth gradient cache ho gaye, xf() ek hi array reuse karta hai) aur Hold: Original ke waqt foreground layer banti hi nahi; nayi photo load hone par purani photo ke wand/cutout/feather scratch buffers chhod diye jate hain aur overlay ka blob URL revoke hota hai; save ab jo blob mila hai usi par bharosa karta hai, isliye jo browser image/webp maangne par chupchaap PNG deta hai wo ab .webp naam ki PNG file nahi likhta — headless Chrome, 1400x1200 par naapa: 60 render me gradient objects 120 -> 0, hold ke 20 frame me putImageData 1 -> 0, 1400x1200 se 420x320 photo swap ke baad zinda typed-array scratch 15.67 MB -> 2.85 MB, PNG-for-webp galat extension wali files 1 -> 0, render ka frame hash bilkul same, zero console errors.
1.1.9 — jo stroke ek bhi pixel nahi badalta (khaali jagah par tap, ya pehle se mitaya hua hissa) wo ab undo history me jagah nahi lete, aur release ke baad pending fast-preview frame cancel hota hai taaki screen wahi dikhaye jo file me save hoti hai; pt() har pointermove par getBoundingClientRect nahi bulata (rect ek baar stroke ke shuru me) aur feather/smooth ka blur ek hi scratch jodi reuse karta hai — headless Chrome, 1400x1200 par naapa: 12 khaali tap ke baad asli edit undo se -1 (kahin nahi) -> 1 press me wapas, per-stroke layout reads 42 -> 1, edge-softness slider ke 12 step par typed-array allocation 36.96 MB -> 0, tap ke baad ka frame final render se match nahi karta tha -> karta hai, save ki PNG byte-identical (112636 B), zero console errors.
